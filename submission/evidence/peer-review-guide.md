# MindCraft 평가자 안내

작성자: Codex /root/v2_wire_review; 현재 상태 갱신: /root/v2_core_review, 2026-09-09, r3. 시험 실행 상태는 EXECUTION_COMPLETE다. 소스26eb06f의 build-z9OSa3에서 최종 패키지3·실제 ConPTY4 및 저장된 실제 Airouter 두 모델 결과 재개방을 검증했다. Code Generation 승인은 완료됐고 최종 Build/Test 승인 상태는 [AI-DLC 상태 기록](../../aidlc-state.md)을 따른다. 이 안내는 AI 채점과 상호 평가의 재현성을 위한 것이며 외부 평가 점수나 미수행 환경의 통과를 주장하지 않는다. [최종 실행 결과](build-and-test-summary.md)와 [r3 AC/Gate 판정](mvp-r3-acceptance-matrix.md)을 함께 확인한다. 이후 문서 갱신은 이미 생성된 소스 ZIP의 바이트를 변경하지 않는다.

Root가 실제 패키지 화면을 확인한 근거: [worker 결과](../mindcraft/evidence/screenshots/r3-packaged-airouter-worker.png), [planner 결과](../mindcraft/evidence/screenshots/r3-packaged-airouter-planner.png). 이 화면은 저장된 실제 응답의 재개방이며 새 API 호출의 근거는 아니다.

## 먼저 실행하기

전달된 `MindCraft-0.1.0-windows-x64.exe`를 쓰기 가능한 별도 폴더에서 실행한다. GUI가 기본이며 작업 자료와 기록은 원래 EXE 폴더에 보관된다. 소스 ZIP을 실행 파일 대신 열 필요는 없다. 개발 도구가 없는 새 Windows에서의 검증은 별도 미완료 항목이다.

저장된 모델이 없으면 첫 화면에 준비 상태와 **1단계 · 작업 폴더 확인**, **2단계 · 모델 연결**이 자동으로 열린다. 실행 환경·기록 저장·모델 설정·연결 상태를 각각 확인한다. **나중에 설정하고 샘플 체험**으로 홈에 이동한 뒤 **먼저 작은 프로젝트를 체험해 보세요**를 누르고, 출처 세 개를 확인한 다음 **이 자료로 진행**을 누른다. **최신 결과 열기**로 완성된 문서를 읽는다. 오프라인 샘플은 모델 호출이나 비용이 없다. 제공자 연결 실패를 샘플 성공으로 대체하지 않는다.

온라인 작업은 홈에서 용도를 선택한 뒤 해당 모드·역할의 모델과 연결 준비 상태를 확인한다. **비용 정보: 미확인**은 가격을 검증하지 않았다는 뜻이다. 다른 제공자의 실제 성공 지원은 여전히 후속이며 Airouter 두 모델의 근거와 혼합하지 않는다.

## 직접 확인할 여정

| 확인할 행동 | 관찰할 결과 |
| --- | --- |
| 자료의 내용·출처 확인 | 어떤 원문이 선택됐는지 확인 가능 |
| 실행 중 새 결과 따라가기 | 명시적으로 켜면 최신 결과를 읽고, 위로 스크롤하거나 저장을 시작하면 멈춤 |
| 결과 읽기·키보드 이동 | 전체 결과가 한 페이지면 Markdown, 여러 페이지면 원문으로 표시하고 결과 영역에 포커스 가능 |
| 파일로 저장 | 경로와 실제 변경 내용을 승인한 뒤 해당 파일 생성 |
| 결과 복사 | 현재 선택한 결과 전체가 복사됨 |
| 자료로 보관 | 자료함 후보에 추가되며 명시적으로 사용 결정 가능 |
| 자료 다시 찾기 | 확정된 자료를 유지하면서 새 검색 결과·출처·부분 결과 확인 |
| 자료함 상세 전환 | 필터 변경·닫기 뒤 늦은 응답이 이전 상세를 다시 열지 않음 |
| 작업 기록 검색 | 빈 검색 결과와 실제 기록 없음 구분, 초기화 가능 |
| 결과 열기 | 같은 작업의 저장된 결과로 복귀 |
| 종료 후 재실행 | 기존 작업과 결과가 보존됨 |
| 다른 인터페이스로 실행 | 같은 workspace에서 GUI 종료 후 CLI/TUI 사용 가능 |
| 좁은 창·확대 | 주요 버튼 접근과 화면 넘침 여부 직접 확인 |
| 실행 상세 정보의 명령 버튼 | 미지원 안내와 비활성 버튼, 클릭·Enter로 명령 대화상자에 진입하지 않음 |
| CLI/TUI에서 `/명령` 입력 | 실행하지 않았다는 안내, 명령 실행이나 승인 요청을 시작하지 않음 |

CLI는 `MindCraft-0.1.0-windows-x64.exe --cli`, TUI는 `--tui`로 연다. `--workspace "C:\검토 자료"`로 같은 폴더를 명시할 수 있다. `/help`로 실제 지원 명령을 확인한다. 같은 폴더의 동시 기록자는 허용하지 않는다.

## 평가 근거와 한계

요구사항별 사실은 [검증 매핑](acceptance-evidence-matrix.md), 재현 명령은 [빌드 안내](build-instructions.md)와 [E2E 안내](e2e-test-instructions.md)를 따른다. author 구현·독립 검토·root 수용·실제 제품 통과를 별도로 기록한다. 상태 변경은 [AI-DLC 상태 이력](../../aidlc-state.md)에서 확인한다.

Airouter의 Qwen3.8 일반 작업(worker)과 DeepSeek-V4-Flash 계획·복잡한 분석(planner)은 실제 인증·응답 및 GUI 재개방 검증을 통과했다. 주소는 `https://api.airouter.ch/v1`이며 인증 키는 배포물에 포함되지 않는다. offline은 모델 미호출 fixture, demo는 실제 Airouter API 문서 작업, user는 비Airouter 제공자 구조다. r3 실제 모델 성공 검증은 명시된 demo의 두 모델이며 다른 제공자의 성공 보장은 후속이다. 모델 목록 연결 확인과 실제 답변 생성을 구별하고 이를 품질 비교로 해석하지 않는다.

재현 workload는 로컬 NTFS UTF8 문서20개×65,536바이트, Knowledge20개×32,768바이트, 합성 baseline 이력100개와 별도 offline fixture Run2개다. 100회 실제 모델 호출이 아니다. [workload 시험](../../../tests/workload-profile.acceptance.ts)의 실제 크기·환경·시간·메모리 관측과 단계별 결과를 확인한다. 테스트 프로세스 관측에는 fixture·기대 본문이 포함되며 native 자식 메모리는 별도 측정되지 않았다면 제외다. GUI·OS 클립보드·실제 provider 증거는 따로 확인한다.

이 수치는 수용 검증 조건이며 강제 입력 상한이 아니다. 더 큰 입력은 성공·성능·메모리 안전을 보장하지 않는다. 큰 본문·Knowledge·맥락·diff는 메모리 부족이나 응답 저하가 생길 수 있다. 원래100GiB 자료+100GiB Knowledge+20GiB 이력, 전체 형식 변환, 전체 cross-page CommonMark/GFM, 큰 diff paging·메모리 보장, 실행 가능한 명령 격리, 전면 clean-Windows/SMB/전원 상실/native IME 조합은 후속이다. 이 항목들을 작은 검사 통과로 채점하지 않는다.

현재 명령 실행은 GUI/CLI/TUI·AI 도구·직접 Core 요청·재시도에서 미지원이며 기존 backend가 실행을 거부해야 한다. 파일·네트워크의 매회 승인·거부 무변경·stale/CAS·보호 저장·손상 보존·mode 경계는 계속 필수다. 후속 기능 이관은 안전조건 면제가 아니다. 이전 제품 검증을 새 r3 EXE 전체의 통과로 자동 승계하지 말고 최종 manifest와 입력 소스를 대조한다.

상호 평가 시에는 수행한 행동, 예상한 결과, 실제 결과, 화면 크기, 재현 단계와 화면을 함께 남긴다. 점수는 평가자가 실제 사용 후 부여하며 이 문서에서 예상 점수를 만들지 않는다. 원시 대화·인증값·내부 추론을 평가 자료에 넣지 않는다.
